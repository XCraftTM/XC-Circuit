# Everything the editor does

| Action | How |
| --- | --- |
| Add a block | Add block in the canvas toolbar (bottom left), right-click empty canvas, or press Space |
| Connect | Drag from a pin to another pin. Holding the wire at an edge of the canvas moves the canvas that way, for blocks out of view |
| Add a connected block | Drag a wire into empty space; the picker shows only compatible blocks |
| Move a block | Drag its title bar |
| Pan / zoom | Drag empty canvas or middle mouse / mouse wheel |
| Templates | File › New Project starts empty or from a working bot, grouped by kind. Discord: Welcome & auto role, Levels & XP, Role menu, Reminders, Moderation, Tickets (with a transcript), Verify with a captcha, New-post alerts, Minecraft server status (in `examples/templates/`). Fluxer: Basic commands, Reminders, Moderation, Verify with a captcha, New-post alerts, Minecraft server status. A plugin adds its own in a `templates` folder; `template.json` gives each its `category` and `icon` |
| JavaScript in texts | Any text field (Send Message, Log, Text, the Embed and Layout Builders …) can hold JavaScript in `${…}`, as in a JavaScript template string: `${user.username}`, `${xp * 2}`, `${member?.nickname ?? user.username}`, `${new Date().getFullYear()}`. `#4` is block #4's outputs: `${#4.message.url}`. Names come from the event, run variables, the block's fields and earlier outputs; a name nothing earlier gives gets an input below the text to connect a value to. A mistake in an expression stops the block with an error naming it. Texts from before, with `{name}`, are changed to `${name}` when a project opens |
| Values from earlier blocks | Type `${` in any text (on a block, in the Inspector or a builder), or right-click it, for the values the block can use. `${` lists the blocks before this one on its action path; pick one and the list slides to its values (`${#1.user}`, the User output of block #1), and › (or →) goes on to a value's members; ← goes back. Typing a name, or a `.` after a value, inside `${…}` lists what fits with its type, like a code editor: `${#1.user.username}`, `${#1.member.roles.highest.name}`, `${#1.user.displayAvatarURL()}`. Run variables are `${name}`. The Embed, Layout and Modal Builders list the values too, under the preview: click one to put it where the text cursor is. **Hide** puts the list away so the preview gets its room (**Show** brings it back); drag the line between the preview and the list to share the room differently |
| Members of Discord values | They come from discord.js itself: `plugins/xc.discord/types/discordjs.classes.json` is made from discord.js's type definitions by `node plugins/xc.discord/tools/discordjs-catalog.js` (run it again after updating discord.js). Only methods that read are listed |
| Message previews | The Embed and Layout Builders show the message as Discord will: with the bot's own name and picture (read from Discord with the saved bot token, when there is one) and each `${…}` as a chip, since its value is only known when the bot runs |
| One path per action | An action output leads to one block: connecting it to another block replaces the old wire. Paths can join, and branch only through blocks made for it (If, Switch, For Each). Older projects with split paths show them in Problems |
| Yes/no inputs | Switches like Private reply can be connected too: click their pin toggle in the Inspector |
| Long text | Text fields on blocks are boxes of a few lines; drag a box's corner down to make it taller or shorter and sideways to make the whole block wider or narrower (the block saves both in the project), double-click the corner to reset them |
| Emoji | Emoji show in colour, as in Discord, with the computer's own emoji font (Segoe UI Emoji on Windows, Noto Color Emoji on Linux); symbols the editor uses as marks (▶ ⚠ ✔ ™ arrows) stay plain. Without an emoji font they're black and white |
| Wider blocks | Blocks that show a message, embed or form (Build Layout, Build Embed, Show Modal …) get as wide as it is in Discord by themselves: a row of buttons fits on one line, and long text stops at Discord's widest and wraps. A block with a big text box gets wider when you drag that box's corner sideways |
| Colors | Click a color swatch for the picker: square and hue bar, hex and RGB, Discord colors and your recent ones. The `${}` button next to it takes a color from the bot instead, such as `${role.hexColor}` or `${color}`: hex, with or without `#` (FF5CA8 works too). Block color fields (Create Role's) can also be a pin to connect a value to; the Embed, Layout and Canvas Builders' colors take `${…}`, each name getting an input on the block |
| Field as pin | Click a field's faint pin, or "pin" in the Inspector |
| More options | Options used less often are folded below **More options** at the bottom of its fields (click it to open or fold them; each block remembers). Folded, an option in use (connected, a pin, or set to something) still shows. The Inspector lists them under More options |
| Accessibility | Settings › Window › Accessibility (on to start with) lets screen readers and the touch keyboard see what's in the window. If XC Circuit stops answering while a program that reads windows runs, try turning it off; freezes.log says whether it was on |
| Select several | Shift-drag a box on empty canvas, or Ctrl+click blocks; Ctrl+A selects all |
| Block actions | Select a block: Duplicate, Try Zone, Note and Delete are buttons above it (Delete key works too), in two rows when the block is narrow. The Inspector's Block source shows the block's source file in its folder |
| Remove a wire | Click it, then its Delete wire button (or press Delete); or drag it off its input and drop it on empty canvas |
| Zoom | The canvas toolbar: − / + , the percentage goes back to 100%, the corners button shows every block; or the mouse wheel |
| Undo / Redo | Ctrl+Z / Ctrl+Y (per workspace). Each workspace keeps 200 steps; Settings › Editor › Undo steps changes that (every step is a copy of the workspace, so fewer use less memory on big projects) |
| Copy / Paste / Duplicate | Ctrl+C / Ctrl+V (at the mouse) / Ctrl+D; works across workspaces and projects. A `${#7.…}` in a pasted text points at the pasted copy of block #7 when it was copied along; Problems lists texts that use a block number the workspace doesn't have |
| First start | The welcome page sets up Node.js (finds it, or installs it: winget or the official installer on Windows, a private copy on Linux), a theme and an accent; Help › Welcome and setup… opens it again |
| Workspaces in order | Drag a workspace above or below another (a line shows where), or onto a folder to move it there. Drag a folder onto the middle of another to put it in there (folders go in folders, as deep as you like), onto its top or bottom edge to put it above or below, or onto the project row to bring it back to the top. While dragging, a label at the pointer says what letting go does ("Into Events", "Below Startup, in Commands"; red where it can't go), the dragged row stays faded in its place, a folder held over for a moment opens, and the list scrolls near its top and bottom edges. A folder's menu has **New folder here**; deleting a folder moves what's in it up a level. The order is saved with the project |
| Side bar | Git, Host and Live session can be dragged there too, like the panels. The activity bar's icon picks what it shows (Workspaces, Search, Git, Stored Data, Live session and Plugins to start with); clicking the one shown folds it away. Two at once: drag an icon (or one of those tabs) onto the side bar's lower half, or right-click an icon › Show in the lower half; it shows under the first, and the line between them drags to share the height. Right-click a half's name to swap the halves, close one, or move it to the main area; clicking an icon that shows hides that half. The icons work like tabs: drag one to reorder them, or out onto the main area to make it a tab there. Drag a tab (Workspaces, Inspector, Console, Problems, the Server console, a plugin's panel) onto the activity bar to make it an icon. Right-click an icon › Move to the main area. View › Side bar and View › Panels tick what's open, as an icon or a tab: untick to take it away, tick to bring it back (Workspaces, Stored Data and Plugins into the activity bar, panels as a tab). Narrow, Settings and Bot settings show their pages as a dropdown |
| Tour | Help › Take the tour: build a tiny bot on a practice project. What to click next glows (the Add block button, the Math entry, the two pins to wire, the Inspector's fields, Run), the card says what to do right now and what went wrong, and Do it for me does any step. Skip any time; arrow keys move between steps |
| Git | Share › Git… keeps the project in a Git repository (GitHub, GitLab, Gitea …): **Store** records what changed and sends it, **Fetch** gets what is stored and puts the two together; files both sides changed are asked about. Sign in with GitHub in the browser, or with an access token. See [Keeping a project in Git](git.md). |
| Live session | Share › Live session… lets several people work in one project at once: one hosts (the project and the bot stay theirs), guests join with an invitation and may change what the host ticks for them. Sealed between the apps; the relay only passes it on. See [Live sessions](live.md). |
| Host | Share › Host… pairs this computer with an XC Circuit Host (a container you run yourself), keeps a project on it, adds further devices by a code, and sends and gets a project's secrets through its vault, sealed on the devices. See [The Host](host.md). |
| Backups | Every save keeps a snapshot outside the project (newest 20, plus one a day for 14 days; Settings › Backups). File › Restore from backup… compares them with now and restores the project or one workspace. Unsaved changes are copied every 30 s (Settings › Backups › Crash recovery) and offered back after a crash |
| Bot data backups | A bot backs up its saved data (store.json) when it starts and every 6 hours, keeping the newest 10 in data/backups. If the data is empty or damaged it asks: restore a backup or start empty (a dialog in XC Circuit, a question in the terminal) |
| Shortcuts | Settings › Shortcuts: click a shortcut and press the keys you want: any key (letters, digits, F1–F24, arrows, punctuation, Home, Insert …) with any mix of Ctrl, Shift and Alt, or the mouse's side buttons. Each action can have two; a shortcut taken from another action says so. Besides Run (F5) and Stop (Shift+F5), Start and Restart alone, Bot settings, Slash Commands, Export, Upload to the server, Server console, Server settings and switching Run between this computer and the server can get one (they have none to start with); menus and the command palette show them. Shortcuts without Ctrl or Alt don't fire while typing. Copy, cut and paste stay the system's keys |
| Settings | Ctrl+, or the gear at the bottom of the activity bar › Settings: theme, accent color (changes live), touch mode, interface size, canvas, window, the Console's font, size and line spacing (any font installed on the computer; monospaced ones first, with a search), bot, plugins, shortcuts |
| Language | English and German come with the app: pick one on the first start page or in Settings › Appearance; it switches right away. Blocks (their names, descriptions and fields) stay in English |
| Touch mode | Settings › Appearance (or the first start's Look step): bigger buttons, rows and pins with more room between them, for touch screens and pens |
| Command palette | Ctrl+P or the search box in the title bar: run any command, open a workspace, or jump to a block |
| Editor tabs | Every tab shows an icon before its name. The Embed Builder, Layout Builder, Modal Builder, Canvas Builder, Slash Commands and Bot settings open as tabs beside the workspaces; drag a tab onto any side or next to other tabs to dock it there. A line or a lit area shows where it goes. Closing a builder's tab cancels it |
| Title bar | Drag to move, double-click to maximize, drag the window edges to resize; View › Use system title bar switches to the system one |
| Save | Ctrl+S (restarts a running bot) |
| Console | Every line with its time and level. Chips show one level: Info, Done, Warnings, Errors, and MCP (what AI agents did) once there is some. The Filter box keeps only lines with its text; Clear empties the Console. Show block jumps to the block that wrote a line |
| Panels | The Inspector, Console and Problems are tabs: drag them to dock anywhere, or onto the activity bar. Right-click a tab › Close or Move to the activity bar; middle-click closes it. Drag the line between two areas to resize them. Reopen closed ones from View › Panels |
| Setup windows | What is set up once and closed again opens in a real window of its own, beside XC Circuit's: New project, Export, Bot › Remote…, importing and exporting workspaces. It has XC Circuit's title bar (or the system's, with Settings › Use system title bar) and can go on another monitor. Git, Host and Live session open the same way once they are no longer an icon in the activity bar |
| Side bar views | Every view has its name on top, its own buttons beside it and a ⋯ menu, and sections that fold away (click a heading; it shows a count). **Search**: type words to find workspaces and blocks by name, number (#12) or what is typed into them; click a block to open its workspace and show it. **Git**: a line for what changed, Store and Fetch, the changed parts by name and the stored versions (right-click one › Go back to this); the gear opens Git's window for where it is stored, signing in and conflicts. **Plugins**: a search, Installed and Built in, each plugin with what it does and who made it; its gear (or a right-click) turns it off, removes it or shows its folder, and + installs one from a .zip file. The Git and Problems icons show how much waits. Right-click the activity bar to tick what is an icon in it, or to hide the bar |
| Start window | Without a project, XC Circuit is a small start window: **Projects** (a search, the recent projects with their kind and Git branch, and New Project, Open, Get from Git), **Live session** (join one with an invitation), **Host**, **Plugins**, **Learn** (the tour, the example bot, the docs, setup) and **Settings** at the bottom. Opening a project turns it into the editor's window, as big and where that was last; File › Close Project brings the start window back |
| Window layout | Buttons at the right of the title bar: **Customize Layout** ticks the activity bar, the side bar, the bottom panels, the right panels and the status bar, and puts the side bar on the left or right; the three beside it hide and show the side bar, the bottom panels and the right panels (also View › Layout). What was in a hidden part comes back with it. The bottom panels' tab bar ends in two buttons: fill the window (and back), and hide |
| Plugin pages | Click a plugin in the Plugins view: its page opens as a tab, with what it is, who made it, how many blocks it adds in which categories, its commands and panels, and its folder |
| Themes | Modern Dark (what a fresh install starts with), Graphite, Midnight and Light come with the app; the gear › Themes or Settings › Appearance switches, and plugins can add more |
| Status bar | Left: the bot's state (click to run or stop it), what waits in Git, the problems, and who is in a live session. Right: Saved, the last upload, the kind of bot (its settings), and an update when there is one. Each opens what it is about |
| Gear menu | The gear at the bottom of the activity bar: Command Palette, Settings, Bot settings, Plugins, Themes and Check for Updates |
| Older computers | Settings › Window › **Lighter drawing**: tick what to leave out, or All: No shadows, No fading, Still glows (no 30-times-a-second redrawing for them) and Simpler edges (about half the triangles); all of them when the app draws without a graphics card, unless that's unticked. **Graphics**: Automatic, OpenGL or Older OpenGL from the next start, for graphics chips that can't do DirectX 12 or Vulkan. Settings › Editor › **Save layout and settings after**: how long after the last change the app saves its layout and settings (5 s to start with; each change in the meantime starts the wait again, and it always saves when it closes) |
| Freezes | When XC Circuit stops answering for three seconds or more (Windows: "Not Responding"; a window that only isn't drawing, while it's moved or minimized, doesn't count), the Console says for how long and where it was stuck, and `freezes.log` in the app's data folder keeps the last 200 such lines. Before the first freeze of a start, it also says how the app draws (and whether in software), whether it's the x86_64 or ARM build and, on Windows, the processor. A freeze the app never came back from (closed while it hung) is said in the Console at the next start. After ten seconds stuck, Windows keeps a dump of exactly where it hangs in the `freezes` folder next to the log (the last three, a few MB each). Send the log, and the newest dump, along when you report a freeze |
| Windows of their own | Drag a tab outside XC Circuit's window and let go, or right-click it › Open in its own window: it gets a window of its own, to put on a second monitor. It looks like XC Circuit's window: drag its tab bar (or a tab) to move it, double-click it to maximize, and its edges to resize; **Back into the app** at the top right (or closing it) brings the tab back into XC Circuit's window, nothing lost. With Settings › Use system title bar it has the system's frame instead. Shortcuts with Ctrl, Alt or a function key (Ctrl+S, F5 …) work there too |
| Workspaces | The Workspaces panel lists them in folders: + and the folder button on the project row add them, drag a workspace onto a folder to move it, double-click a name to rename. Ctrl-click workspaces to select several (Ctrl-click again to take one out), or Shift-click to select all from the last one clicked; **Delete** then asks before deleting them, and so does Delete N workspaces in the menu of a selected one. Clicking elsewhere (or Escape) lets go of the selection, so Delete deletes blocks again. On the right of each: a warning sign and number for its problems, a green dot while its blocks run (red after one failed), and **off** when it's turned off; folders show how many workspaces they hold (and, closed, their problems). Hover a workspace for its blocks, events, problems and when it last ran. The ⋯ button (or right-click) has Open, Rename, **Duplicate** (a copy with all its blocks, turned off so it doesn't answer twice), Turn off/on, Move to, Export and Delete. **Turn off** leaves a workspace out of the bot (its events don't fire, its blocks don't run) without deleting it |
| Snap and arrange | The magnet in the canvas toolbar (or Settings › Canvas) snaps dropped blocks and notes to the grid. With several blocks selected, Arrange above them aligns their edges or centres, or spreads them out evenly |
| Run times and values | While the bot runs from the editor, each block shows how long it took above its corner for 30 seconds, and hovering a wire shows the last value that went through it |
| Favourite blocks | Star a block in the picker (on its row or in its details): favourites and the blocks you placed lately are listed at the top |
| Notes | Add note in the canvas toolbar, or select blocks › Note to frame them: a title, a description and a colour (pencil button or double-click the title; a preset, or Other color for any colour; the boxes grow by their corner grip). Drag the title to move the note; with its "Move blocks with the note" switch on (off for new notes), the blocks inside move along. Alt does the opposite for one drag; drag its edges or corners to resize it. Zoomed out, a note's title and description stay readable, like a map's labels (the description only while it fits in half the note). Notes don't run |
| Try Zone | Select a block › Try Zone; drop blocks in or out; the gear on the zone's title sets retries and timeout |
| Embeds | Select a Build Embed block › Open Embed Builder; the block shows a live preview. Every part of an embed is there: author with link and icon, title link, fields, images, footer, and a timestamp (when it's sent, or a set time) |
| Pictures | Select a Build Canvas block › Edit canvas…: the Canvas Builder. Start from a Rank, Welcome or Profile card; add shapes, circles, pictures, texts and bars; click to choose a layer, drag to move it, drag its corner to resize it (Shift keeps its shape), arrow keys to nudge it. Preview values show `${…}` with a value. The block shows the picture ([Pictures with Build Canvas](./canvas)) |
| Forms (modals) | Show Modal's form is designed in the Modal Builder (Edit form… on the block, or Open Modal Builder in the Inspector): a title, a custom id (what Modal Submitted matches) and up to 5 parts: questions, each with a hint and a box to type into (one line or several), a select menu (options you list, users, roles or channels) or a file upload, and texts with markdown. A preview shows it as Discord will. Modal Submitted (with the form's custom id) gives each answer as an output of its own, of its kind, by itself: a box's text, the values picked from a menu of options, the members, roles or channels picked from such a menu (as lists), the files of an upload. Its Input ids is only for forms made from blocks; ids listed there give text. The JSON view takes a modal pasted from the Discord docs. Forms made from Text Input, Form Field, File Upload and Form Text blocks wired into Show Modal's Inputs keep working; those blocks are no longer in the picker |
| Picking channels and roles | With a bot token saved, fields for a channel, category or role id (and Find Role, Find Channel, Add Role, Has Role) have a small button after the box: it lists your bot's servers with their channels (of the right kind) or roles, and puts the id of the one you pick in. Its tooltip names the one chosen. No more copying ids with Developer Mode |
| Custom ids | Button Pressed, Select Menu Used and Modal Submitted offer the custom ids your layouts, forms and Button / Select Menu blocks use (Custom… types any other, such as one made while the bot runs). Problems says when an event waits for an id nothing has (often a typo) and when a button, menu or form has no event to handle it |
| Discord's limits | The Embed, Layout, Modal and Slash Command Builders check what Discord would refuse, with its own limits: an embed's title (256 characters), description (4096), fields (25, names 256, values 1024), footer (2048), author (256) and 6000 in all; a button's label (80) and link (512, starting with https://); a select menu's placeholder (150), how many can be picked (up to 25) and its options (labels, values and descriptions up to 100, values each their own); pictures' descriptions (1024); a form's boxes (placeholder 100, filled-in text 4000) and file uploads (up to 10 files and 10 file types); a command's required options before optional ones, each option name once, up to 25 subcommands and 8000 characters in all. What a `${…}` becomes isn't counted, as it's only known when the bot runs. The builder lists them above its form, and blocks with such a design show them in Problems |
| Components V2 | A Build Layout block designs a whole message from Discord's components: containers with an accent color, text (markdown), sections with a picture or button next to the text, media galleries, files, separators, rows of buttons (every style, emoji, link and premium) and select menus (options, users, roles, channels). Edit layout… opens the Layout Builder with a Discord preview; set Send Message's Format to Layout and connect the block. Pictures and files given as file paths are attached when sending |
| JSON | The Embed Builder, Layout Builder, Modal Builder and Slash Commands each switch between Builder and JSON. The JSON is Discord's own: edit it or paste JSON from the Discord docs, discord.js `toJSON()` or a message designer, and it applies as soon as it is valid (errors show the line and column) |
| Slash commands | Bot › Slash Commands…: options with choices (a name and a value each), length and number limits, channel kinds and autocomplete; subcommands and groups; translations of every name and description into Discord's languages; the permissions people need (any number), where the command works (servers, DMs with the bot, other DMs), how the bot is installed (server or account) and age-restricted. Registered when the bot starts, and checked against Discord at every start. In the side bar, under Slash commands: click one to edit it, drag them into order or into folders (the folder button makes one; folders go in folders, as for workspaces), and turn one off (right-click) so it isn't registered |
| Databases | Bot › Settings › Databases: connections to MariaDB, MySQL, PostgreSQL, SQLite or MongoDB, each with Test connection; the default database; where stored values are kept. The blocks Get Rows, Insert Row, Update Rows, Delete Rows and SQL Query use them ([Databases](./databases)) |
| Stored data | Stored Data (the database icon in the activity bar) shows what `ctx.store` saved: add, change or delete values (read-only while the bot runs). Pick a database at the top to see its tables as a grid: page through the rows, double-click a cell to change it, Change and Delete in front of each row, Add row |
| Plugins | The Plugins view of the side bar: every plugin and how it runs, Install…, Reload, Open folder. A switch turns a plugin off or on; the trash can removes it (after asking). The plugins that come with the app can't be turned off or removed |
| Bot settings | Bot › Settings: pages on the left (Connection, Slash commands, Messages, Music, Privileged intents, and pages plugins add), the page on the right, Save at the bottom. A page with something required but unset shows a count in the list, one with a value that doesn't fit shows it in red |
| Bot token | Bot › Settings › Connection (kept in Windows Credential Manager / Linux Secret Service). The eye button shows what you typed, Copy copies the saved token without showing it, and values are checked as you type (a build mode's settings can set `pattern`, a regular expression, and `patternHint`; `sensitive = true` hides a text setting behind the eye button) |
| Invite your bot | Under the bot token, once one is typed or saved: pick the permissions (**What your blocks need**, made from the project's blocks and listed under it, or common bot permissions, Administrator or none), then **Open invite page** opens Discord's page for adding the bot to a server, or **Copy link** copies the link |
| Run / Stop | F5 / Shift+F5, or Run in the title bar. Running blocks glow; failures show on the block |
| Export | Bot › Export… writes a folder that runs with `node index.js` |
| Remote | Bot › Remote… uploads the bot to its server over SFTP or a Calagopus panel, by hand or after every save; only changed files are sent, and the server's `data/` is never touched. For a Calagopus server, sign in through the browser; Bot › Remote console has Start, Restart, Stop, Kill and the live console ([Putting your bot on a server](./hosting)) |

Running needs Node.js 22 or newer; the first start page (or Settings › Bot › Node.js) finds or installs it. The first run installs the mode's npm packages (discord.js, or @fluxerjs/core for Fluxer bots) once, into `%APPDATA%\XC Circuit\packages` or `~/.local/share/xc-circuit/packages`.
